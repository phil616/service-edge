# FRP 稳定性修复：第一批

对应 [架构审查](frp-architecture-audit.md)，该审查记录的是修复前状态。

## 已实现

- 删除路径限定为单个实例；停止、禁用失败时保留文件和本地记录，等待重试。
- FRPC 连接新增每 10 秒的轻量报告，保留原主机详细报告周期。最多 4 个并行采集任务，每个实例 2 秒、整批 8 秒预算；上传独立预算 15 秒。未成功采集的实例也上报明确错误。
- 新 Agent 的连接观测有效期最低 60 秒；旧 Agent 的默认详细报告按 240 秒有效期兼容。过期或宿主机失联显示“状态未知”，不再把未及时采样误报成确定断线。
- 分开保存代理配置启用状态与运行状态；Admin API 失败、缺失代理、新配置尚未应用显示未知；代理异常不再自动禁用配置和反复重启。
- FRPS 目标二进制版本不再被状态上报覆盖。磁盘上的二进制版本单独展示，不冒充运行进程版本。
- 每个连接的应用指纹包含配置内容、CA 和目标二进制版本；共享版本/CA 变化会重新应用实例，仅配置修订号变化可直接确认而不重启。
- 连接级成功状态立即持久化；部分成功后 Agent 重启不会丢失已完成进度。保存失败恢复内存旧状态并报告失败。
- 应用、删除与 watchdog 互斥；watchdog 重启预算按实例计算。
- 控制面持久保存已应用版本和应用错误，忽略旧版本以及成功后到达的同版本失败 ACK；心跳/详细报告可补偿丢失的成功 ACK。
- 状态持久化在数据库事务中完成，错误返回 Agent；上报连接严格限制在其所属宿主机。
- 长轮询先订阅再检查版本，超时再次检查；Agent 配置的长轮询超时实际生效，并校验计时参数。
- FRPC Agent 启动和每约 5 分钟请求完整快照，校准文件缺失及旧状态；相同指纹且文件齐全时不重启。
- systemctl、配置校验、版本命令有超时；FRPS 列表增加定时刷新，详情页展示目标/已应用版本和代理观测状态。

## 发布与兼容

1. 先更新控制面，再更新 Agent。新轻量报告需要控制面识别 `connections_only`，不能先部署到仍使用旧控制面的 Agent。
2. 控制面启动通过现有 AutoMigrate 添加运行状态字段。旧 Agent 仍可上报；没有提供的观测信息显示未知。
3. 首次升级 Agent 时，旧 state.json 没有应用指纹，因此完整快照会重新应用已有 FRPC 实例。这包含逐实例重启，应在可接受的维护窗口执行。之后指纹相同的完整快照不会重启。
4. 原有由运行错误写成 inactive 的映射不会被批量自动启用；确认配置与端口条件后可在界面编辑保存恢复，避免升级时意外开启映射。
5. 已被旧删除缺陷清除的文件可由完整快照重建；前提是控制面仍保有对应连接和配置。若控制面记录也已删除，则需要从备份恢复。

本次仅修改工作区，没有部署到实际节点。

## 验证范围

新增回归测试覆盖真实临时目录删除隔离、删除失败、状态保存失败/重启恢复、二进制/CA 指纹、Admin API 错误、并发采集超时及失败结果上传、启动完整同步、旧 Agent 兼容、观测租约、代理异常不改配置、版本单调性、丢 ACK 补偿、跨宿主机上报隔离、数据库事务回滚。

运行检查：`go test -race ./...`、`go vet ./...`、`npm run build`（web 目录）。

## 尚未包含

- 真实 frps/frpc 多机故障注入和公网端到端连通验证。
- 业务 RTT、吞吐和活动连接指标采集；未采集的活动连接指标不显示为确定的零。
- frp 会话与业务后端健康的完整独立模型；“代理已注册”不等于业务端到端可用。
- 代理 Admin 热更新、配置/证书/二进制整组回滚、跨 Agent 会话的报告序号与持久失败事件重试。
- 所有配置修改和跨对象版本推进的事务重构、控制面数据库恢复后的全局 epoch 协议。

本批修复解决确定缺陷并建立状态分层基础，不宣称整体架构审查中的所有后续事项均已完成。
